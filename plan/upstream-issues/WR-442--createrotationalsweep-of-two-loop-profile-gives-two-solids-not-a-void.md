#### WR-442. `SmApiCreateRotationalSweep` of a profile with two closed loops (a hollow sphere) gives two solid regions, not a solid with a void (SolidCraft #451)
- **Severity:** Wrong result (the inner sphere is a second solid, so cutting with the "hollow" tool removes the hollow's contents and leaves the outer sphere filled)
- **Area:** Topology / primitive creation
- **Location:** `source/SMLib/src/SmPrimitiveCreation.cpp`, `CreateRotationalSweep` (2565-2772) -> `StitchAndOrient`; `source/SMLib/src/SmMerge.cpp:1698` (comment: nested shells may not work).
- **What happens:** the half-ring profile (line 18.5..40 on the axis, arc r 40, line -40..-18.5, arc r 18.5, axis X, 360 degrees) sweeps to two closed shells. Nothing in the sweep nests the inner shell into the outer one: oriented, each shell becomes its own solid region, with both listed in the infinite region. No void region exists.
- **Trigger:** a rotational sweep whose profile has two closed loops, one inside the other once revolved.
- **How found:** SolidCraft #451 (hollow shell cut, `fixtures/solidcraft/451-hollow-shell-cut.json`). Expected volume 241560.726 = V(r40) - V(r18.5); got 294604.425 = V(r40) + V(r18.5).
- **Confirmed:** yes, C++ run in the `solidcore-arm` container, 3 runs identical. Essential calls: `SmApiCreateLineSegment` x2 and `SmApiCreateArc(o, 40|18.5, 0, 180)` for the profile, `SmApiCreateRotationalSweep(curves, o, (1,0,0), 360.0, 1, brep)`, then `SmApiBrepMaterialCensus` and `SmApiBrepComputeVolume`. Result: 3 regions (the infinite one with 2 shells, two solid regions with 1 shell each), census solids=2 voids=0, volume 294604.424735. Control `SmApiBooleanDifference(SmApiCreateSphere r40, SmApiCreateSphere r18.5)` is correct: 3 regions, one solid region with 2 shells, one void, solids=1 voids=1, volume 241560.726219. The Rust port gives the same as C++ for both.
- **Fix:** none in the port (faithful to the pinned reference). A nesting step after stitching, assigning a shell lying inside another to a void region, would fix it; difftest cases that rely on it follow SMLib and are not Rust divergences.
- **Rust port:** `crates/solidcore/src/topology/brep/` (`orient_ray_votes`), unchanged.

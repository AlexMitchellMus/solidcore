#### WR-423. Precise face-property integration can miss UV trim features between adaptive sample points
- **Severity:** Wrong result
- **Area:** Numerical integration
- **Location:** `source/SMLib/src/SmFace.cpp:6002`, `SmFace::ComputePreciseProperties`; `source/SMLib/src/SmIntegrator.cpp:368`, `SmODEIntegrator::RungeKutta5thOrderStep`.
- **What happens:** face properties integrate each entire oriented trim without stopping at its spline knots. The Cash-Karp embedded error estimate samples finitely many points; when those points miss a narrow feature, the call can report success with a wrong area. Smaller initial steps are retried only on failure, so that retry does not address false convergence.
- **Trigger:** a planar rectangle of area 0.1 with a triangular feature of area 0.005 on its upper UV boundary. A degree-one spline has knots `[0, 0.61, 0.615, 0.62, 1]`, multiplicities `[2,1,1,1,2]`, and points `[(1,.1),(.39,.1),(.385,1.1),(.38,.1),(0,.1)]`; three lines close the left, bottom and right. Whole-curve integration misses the feature, returning 0.1 at requested accuracy `1e-10`; integration by knot spans recovers 0.105. The Rust regression is `issue_1105_trim_knot_properties`.
- **How found:** investigation of tangency-labs/solidcore#1105, the existing Windows GNU radius-5 pole-free sphere analytic test failure. Source review and isolated integration experiments localized its deficit to whole-trim adaptive integration. See `plan/findings/mass.integrator--trim-knot-steps-issue-1105.md` for values and limitations.
- **Confirmed:** not yet on the native C++ build for the focused planar feature or Windows sphere failure. Linux pinned C++ and Rust agree bit for bit on the complete sphere and pass the existing analytic limit there. This does not establish a native Windows failure or identify the first platform-divergent adaptive step.
- **Rust port:** opt-in `Kernel::fixes.precise_properties_at_trim_knots` integrates each trim knot span, sharing the outer absolute error-scale floor among spans. Upstream defaults, caller accuracy and existing analytic tolerances remain unchanged. The original default-mode Windows test still fails; the opt-in result must not be reported as fixing that default gate.

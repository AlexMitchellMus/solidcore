#### WR-511. `SmSurfOfExtrusion::AssertValid` test 8 point-solves its origin with an unscaled `SM_EFF_ZERO`, so a valid extrusion at coordinates of about 10 fails "origin is a point on the generating curve"
- **Severity:** Wrong result
- **Area:** Surfaces and volumes
- **Location:** `source/SMLib/src/SmSurfOfExtrusion.cpp:4153` (test 8; the `GlobalPointSolve` at `:4156`), `SmSurfOfExtrusion::AssertValid` (def. `:4049`).
- **Pinned reference:** SMLib v1.0.1, commit `3fd5b95`.
- **What happens:** Test 8 calls `m_pGenCurve->GlobalPointSolve(..., SM_SO_INTERSECT, m_vOrigin, SM_EFF_ZERO, ...)` and reports the origin missing when the solve returns no solution. At coordinates of about 10 the solve resolves an origin that was evaluated on the curve to a few 1e-12, past the unscaled 1e-12, so a valid extrusion is refused. The check's other point tests scale their zero by the point's size (tests 5/6 use `SM_EFF_ZERO_SQRT`; test 9/11 use the point's dimensions).
- **Trigger:** `SmSurfOfExtrusion::AssertValid` on an extrusion of a quadratic Bezier at coordinates of about 10 (a text outline's letter), whose origin was evaluated on the generating curve.
- **How found:** issue tangency-labs/solidcore#1508 (SolidCraft text-outline sweep; fork tangency-labs/smlib#31). Read during porting; the port's production `Surface::assert_valid` reports the same test-8 failure for a translated quadratic generator, and the regression test `crates/solidcore/tests/issue_1508_extrusion_origin_scaled_zero.rs` exercises the issue's scale with the solve's residual. The pinned C++ override is also compared through `surface.surface_assert_valid` shim kind 7 (ordinary and translated extrusions, full report vector).
- **Confirmed:** no. The issue's exact test-8 case at coordinates of about 10 was not generated for the C++ comparison, so the defect report itself is not confirmed; the issue's capi `sweeps.cpp` test is the reported confirmation. The port's opt-in regression is `crates/solidcore/tests/issue_1508_extrusion_origin_scaled_zero.rs`.

The fork's correction is `SM_EFF_ZERO * (1.0 + m_vOrigin.GetMaxDimension())`. The port keeps the pinned C++ result by default and applies it only with the opt-in, default-off `Kernel::fixes.extrusion_origin_scaled_zero` (`crates/solidcore/src/kernel.rs`), so the default path follows the pinned reference and difftest tolerances are unchanged.
